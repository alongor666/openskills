三层只读模型

网络层
谁能连到这台机器　公司内网互通（SMB 445 通常已放行）；绝不公网映射 / DMZ
共享层
暴露的是什么　只读副本目录：SMB ReadAccess ＋ NTFS RX，操作系统级强制只读
账号层
谁能拿、拿多少　共享 / 数据库只读账号一人一号（或按组），敏感字段先脱敏，人走即撤

主路径五步（通道 A）

先完成上方「动手前：先探后问」，再按五步执行；需本地管理员权限。脚本默认 dry-run，确认计划后加 -Apply。

1

建两个目录 本机私有 / 对外只读，分开

New-Item -ItemType Directory -Force -Path D:\DbStage, D:\DbShare
DbStage 放导出件（谁都不共享）；DbShare 是唯一对外的只读目录。
2

按库安全导出快照到 DbStage 别裸拷正在写的文件

库安全快照命令
SQLitesqlite3 源库.db ".backup 'D:\DbStage\copy.db'"（在线备份，运行中也安全）
DuckDB停写窗口直接复制；在写时 EXPORT DATABASE 'D:\DbStage\db' (FORMAT PARQUET);
Access / Excel关闭文件后直接复制
SQL Serversqlcmd -E -Q "BACKUP DATABASE [库名] TO DISK='D:\DbStage\库名.bak'"
MySQLmysqldump --single-transaction -u 用户 -p 库名 > D:\DbStage\库名.sql
PostgreSQLpg_dump -U 用户 -f D:\DbStage\库名.sql 库名
3

镜像 ＋ 建 SMB 只读共享 snapshot-share.ps1

# 无域环境先建共享账号（域环境 -GrantAccount 直接填域组，如 DOMAIN\dept-group）
New-LocalUser -Name dbreader -Password (Read-Host -AsSecureString '密码') -AccountNeverExpires

# 先 dry-run 看计划，确认后加 -Apply（需管理员）
pwsh -File scripts\snapshot-share.ps1 -StageDir D:\DbStage -ShareDir D:\DbShare -ShareName DbShare -GrantAccount dbreader -Apply
脚本做三件事：robocopy 镜像 → NTFS 只授权（RX）→ New-SmbShare -ReadAccess 操作系统级只读。
4

定时快照 数据新鲜度 = 快照周期

schtasks /Create /TN DbSnapshot-Hourly /SC HOURLY /TR "pwsh -NoProfile -File D:\dbshare\scripts\snapshot-share.ps1 -StageDir D:\DbStage -ShareDir D:\DbShare -Apply"
5

体检 ＋ 交接 verify-access.ps1

# 服务器侧一键体检：共享存在 / 目录非空 / 445 监听 / 打印给同事的地址
pwsh -File scripts\verify-access.ps1 -ShareName DbShare

# 同事侧两连验证
Test-NetConnection <服务器IP> -Port 445      # True 才算通
dir \\<服务器IP>\DbShare                     # 能列出快照文件
共享期间把服务器电源设为「从不睡眠」——一睡眠同事全部失联。

分支：只读账号直连（通道 B，要实时才用）

能不用就不用——直连动了生产库本体。按库建只读账号，再只对公司内网网段放行端口：

库只读账号端口
SQL ServerALTER ROLE db_datareader ADD MEMBER ro1433
MySQLCREATE USER 'ro'@'192.168.%' → GRANT SELECT ON 库名.*3306
PostgreSQL只读角色：CONNECT ＋ USAGE ＋ SELECT5432
pwsh -File scripts\setup-firewall.ps1 -Port 1433 -ScopeSubnet 192.168.0.0/16 -Apply
按实际办公网段填 ScopeSubnet，禁止 any；强密码定期轮换，人走即撤。

工具箱（4 个零依赖 PowerShell 脚本）

probe-env.ps1 第 0 步

只读环境探针：管理员权限 / 库型 / 网络档位 / 磁盘 / 共享冲突 / 导出工具。动手前先跑。

snapshot-share.ps1 通道 A

robocopy 镜像快照目录 ＋ 建 SMB 只读共享 ＋ NTFS 只读授权。主路径核心。

verify-access.ps1 通道 A

服务器侧体检：共享存在 / 目录非空 / 445 监听 / 打印给同事的地址。

setup-firewall.ps1 通道 B

数据库端口入站放行，必须限定内网网段（-ScopeSubnet）。

红线（开放期间全程有效）

脱敏优先　客户敏感字段（姓名 / 证件号 / 手机号）能去则去；共享范围最小必要，遵守公司数据制度，敏感范围先审批。
原件不出门　数据库原件、代码目录、配置文件（含连接串密码）绝不进共享目录。
账号最小化　一人一号（或按组），强密码定期轮换，人员变动立即撤。
只在内网　一切端口只对公司内网网段开放；禁止公网映射、禁止路由器 DMZ。
别拖垮生产　快照周期按研究可接受的新鲜度定，不做高频导出。

故障排查

症状大概率原因处置
同事打不开 \\IP\DbShare / 要密码共享账号没建对、GrantAccount 没配服务器侧跑 verify-access.ps1，核对共享 ReadAccess
共享看得到但里面是空的快照没导出 / Stage 路径不对手动跑一次 snapshot-share.ps1 -Apply 看 robocopy 结果
Test-NetConnection 445 失败445 被禁 / 跨网段不通查「文件和打印机共享」防火墙规则；联系 IT
副本文件打不开 / 损坏裸拷了正在写的库文件改用第 4 节各库安全导出命令
直连 1433/3306/5432 拒绝端口没放行 / 只读账号没建setup-firewall.ps1 ＋ 直连分支账号命令

收口：不用了就撤干净

Remove-SmbShare -Name DbShare -Force                        # 撤共享
Remove-LocalUser -Name dbreader                             # 撤共享账号（无域时）
Remove-NetFirewallRule -DisplayName IntranetDbReadonly-1433 # 直连路径撤端口
schtasks /Delete /TN DbSnapshot-Hourly /F                   # 撤定时快照
